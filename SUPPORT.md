# Support

The default support policy for `akira-toriyama` repositories that don't ship
their own. These are personal projects maintained on a best-effort basis — there
is no SLA, but issues and questions are welcome.

## Getting help

- **Questions & bug reports** — open an issue **on the specific project's own
  repository** (not this `.github` repo, which only holds shared CI and the
  org-default community-health files). Use the project's issue templates so the
  right details land in the right place; the plain blank-issue path stays open for
  quick questions.
- **Install / Homebrew problems** for the published apps — include your OS
  version, the app version (`--version` or the About panel), and the exact
  command or steps that failed.
- **Security vulnerabilities** — do **not** open a public issue. Follow
  [`SECURITY.md`](SECURITY.md) (private advisory or email).

## Before opening an issue

- Check the project's README and any existing open/closed issues first.
- Include a minimal reproduction and what you expected vs. what happened.
