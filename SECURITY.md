# Security policy

The default security policy for `akira-toriyama` repositories that don't ship
their own. Thanks for helping keep these projects safe.

## Reporting a vulnerability

**Please do not open public issues for security bugs.** Report privately —
either channel works:

- **GitHub advisory:** if this repository has **Security → Report a
  vulnerability**, use it to open a private advisory. (See GitHub's
  [private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability).)
  This button only appears when the repository has it enabled — if it's absent,
  use email.
- **Email (always works):** [akira.toriyama.dev@gmail.com](mailto:akira.toriyama.dev@gmail.com)
  — put the repository name in the subject so it's easy to triage.

Please include:

- the version (or commit) you're running,
- a minimal reproduction, and
- the impact you observed and any mitigations you've considered.

I aim to acknowledge within 7 days and to coordinate disclosure on a timeline
that matches the severity. There is no bug bounty.

## Supported versions

The latest release on `main` is supported. Older releases get fixes only by
upgrading.
